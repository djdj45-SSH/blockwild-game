# 方块荒野 BLOCKWILD

> 一片程序生成的方块大陆，怪物从林子、废墟和沙漠里不断涌来。找到补给箱换更好的枪，活得更久，走得更远。

开放世界 · **低模体素 3D** · 第一人称射击 · 肉鸽词条 · 局域网联机

技术栈：**Three.js / WebGL + Vite**（模型与贴图 100% 程序化生成，无任何外部美术资源）

## 快速开始

```bash
npm install
npm run build      # 产出 dist/
npm run server     # http://localhost:8080  （单人 + 局域网联机，控制台会打印局域网地址）
```

开发时可 `npm run dev`（Vite 热更新）。注意：**联机必须走 `npm run server`**，
纯静态托管（如 GitHub Pages）跑不了 `server.js`，且 https 页面会被浏览器拦截 `ws://`。

## 渲染架构（性能相关，改动前务必看）

| 手段 | 说明 |
| --- | --- |
| **纹理图集** | 12 张程序化像素贴图打进一张图集（4×4 格、每格 256²+16px 护栏），所有方块类型共用一个材质 |
| **分块网格** | 地形按 32×32 分块合并成 1 个 mesh/块，视锥 + 距离剔除 |
| **顶点色调制** | 方块类型色调烘进顶点色，避免逐类型多材质 |
| **阴影节流** | `shadowMap.autoUpdate=false`，隔帧更新；贴图分辨率随画质档位切换 |
| **实体合并** | 每只怪的所有零件在"动画节点"内合并成 1 个顶点色网格（20+ draw call → 6） |
| **几何缓存** | 盒/柱/球按尺寸缓存复用，生成销毁实体不再重复造 GPU 缓冲 |
| **粒子实例化** | 全部粒子走一个 InstancedMesh（1 个 draw call） |
| **实体预算** | 敌人按距离取最近 24 只渲染，超出直接隐藏（雾里看不见） |
| **小地图节流** | 8Hz 重绘，且只画周围 34 格 |

画质档位（低 0.4 / 中 0.7 / 高 1.0 / 高清 1.5 / 超清 2.2）是**真实分辨率倍率**，
帧时间超过 21ms 会自动逐级降档（最多 3 次，不低于 0.45×）。

## 美术规范（Minecraft 原版取向）

产品方向在 2026-09-17 拍板为「明亮卡通，参考《我的世界》」，
2026-10-05 进一步明确为**直接使用原版资源**，目标是"跟我的世界一样"。
**任何"写实化"或"自创风格"的改动都视为方向错误。**

### 资源来源（2026-10-05 起：从程序化改为原版素材）

两条脚本，产物已内联进仓库，运行时**不需要联网**：

```
python tools/fetch-mc-textures.py     # 从 Mojang 官方 client jar 抽 25 张方块图 + 8 张角色图
python tools/build-mc-atlas.py        # 拼成图集 → src/three/mc-{atlas,entity}-data.js
```

- 走**官方 client jar**（`piston-meta.mojang.com` → version manifest → client.jar）
  而不是第三方资源包：分辨率、调色板、镂空 alpha 全部是游戏实际使用的那份，没有二次改色。
- 图集以 **base64 内联进 JS**。项目同时支持「源码根 + importmap 纯静态托管」和
  「vite build 产物」两种部署，`import` 图片在浏览器里直接报错、相对 URL 在构建后层级会变，
  data URL 两种都零成本生效，还省一次请求。
- 原始 PNG 留在 `assets/mc/`（方块 25 张）与 `assets/mc/entity/`（角色 8 张），
  重新生成图集时不用再联网。

### ⚠️ 原版纹理的三个坑（不知道就会一脸灰白）

1. **`grass_block_top` / `oak_leaves` / `water_still` 是灰度图**。
   Minecraft 把它们的颜色在运行时用 biome color 乘上去（colormap）。
   直接贴会得到一片灰白 —— 这不是纹理坏了，是**缺了染色这一步**。
   现在在 `WALL_SKIN` / `FLOOR_SKIN` 的 `color` 里补上原版 plains 默认色：
   草 `0x91BD59`、叶 `0x77AB2F`、水 `0x3F76E4`。**其余方块一律 `0xffffff`**。
2. **方块图是 16×16，角色图是 64×64 / 64×32**，且角色 UV 是跨整张皮肤精确切分的
   （相邻面紧挨着）。所以角色纹理必须 `minFilter = NearestFilter` + 关 mipmap
   （原版就是 `mipmapping: 0`）—— 开 mip 会让脸和侧面互相串色。
3. **树叶镂空的 `alphaTest` 给 0.1，不要给 0.35**。树叶 alpha 是二值的 0/1，
   0.1 已经足够丢掉全透明像素；给高了会把远处 mip 混合出的中间 alpha 一起丢掉，
   整片树冠被打成"绿网"、远处直接消失。

### 方块纹理（`src/three/textures.js`）

- 图集布局由 `tools/build-mc-atlas.py` 决定，**改图集必须同步改布局常量**
  （脚本会把 `LAYOUT` 打印出来）。
- 每格四周留 `ATLAS_PAD = 16` 护栏（边缘像素向外延伸）：mipmap 缩小时双线性会在
  格子边界采到隔壁材质 → 远处出现"彩色描边"。护栏宽度要能撑到 mip 4。
- 过滤：`magFilter = NearestFilter`（放大硬边）+ `minFilter = NearestMipmapLinearFilter`
  （缩小走 mipmap，避免远处摩尔纹闪烁）。

### 光照与天空

- `exposure 1.15` / `sun 1.55`（仰角 **36°**）/ `ambient 0.30` / `hemi 0.34` /
  `fill 0.16` / `rim 0.12` / `environmentIntensity 0.22`。
  目标：受光面 ≈ 反照率×1.9、侧面 ×1.4、背光面 ×0.6（明暗拉开 3 倍）。
- **太阳仰角别抬高**：43° 以上时影子缩在方块脚下，画面立刻变平；36° 时影长 ≈ 1.4×物高。
  太阳方位存在 `R.sunOffset`（相对相机的偏移），改角度改这里，别散落在两处。
- **环境光要接近中性**（`0xe6eef6`）：给蓝会让石头/石砖地面整体泛蓝，
  一片地板变成"蓝灰色"；明亮感来自色彩饱和，不是把亮度拉满（1.35 曝光时树叶被打成亮黄绿）。
- **环境光占比别超过太阳的 1/3**：`ambient + hemi` 曾经合计 0.91（≈太阳的 0.85 倍），
  受光面与背光面只差 1.4 倍，整幅画面像蒙了层塑料膜 —— 这是"画面发平"的头号原因。
- 天空 = 明亮蔚蓝三段渐变 + **方块状白云**。云必须用**射线与云平面求交**得到交点坐标再量化，
  详见"血泪结论"。雾色必须与地平线同色系（`0xcfe8fa`），灰雾会让远景发闷。
- 太阳画成**方块**（在垂直于 `sunDir` 的平面上两个轴同时 `step`），这是最强的风格符号之一。
- 发光件（红石/岩浆）emissive 强度不要给满：它与 diffuse 叠加，红色通道最先饱和，
  拉满时熔岩管会糊成一块纯橙色塑料，纹理细节全丢。

### 地形着色（`render3d.js` 的 pushQuad / pushTop / pushSide）

- **顶点色是线性空间**：`tintOf(hex, k)` 里 `k` 是线性倍数，屏幕上表现为 `k^(1/2.4)`。
  想要"视觉上暗 30%"就得给 `k ≈ 0.42`，给 0.7 屏幕上只暗 13% ——
  **这是 AO / 色差 / 各面明暗差全部没效果的真凶**，换算：`k_linear ≈ ratio^2.4`。
- **顶点级 AO**（Minecraft smooth lighting）分两半，都要有：
  ① 地面格子按**四角**各自查相邻墙压暗（整格统一压暗毫无作用）；
  ② 墙面**最下面一段的底部两个顶点**压暗（墙脚接触阴影，少了它所有墙都像浮在草地上）。
- **地面色差三层**：两个不同尺度的 `vnoise`（双线性插值，**不能用 hash(floor) 直接取整**，
  那样俯视就是一张硬边棋盘）+ 逐格高频。振幅要按线性空间给（`0.875 ~ 1.105` 才够看）。
- **UV 逐格随机旋转**（`(x*7 + z*13) & 3`）：大面积同种方块靠这个打散"刷了一整块"的机械感。
  不要复用按 2×2 分块的 hash，那样仍能看出规律。
- **墙高表全是非整数**（2.0/1.9/2.2/2.85/2.45…）：`pushSide` 必须**按固定 1 米分段、顶段吃余数**，
  用 `h/round(h)` 等分会把纹理非均匀拉伸（h=2.45 → 拉长 22%，树叶侧面直接变横条纹）。
- **顶面/侧面明度差照搬 Minecraft 的固定系数表**：顶 1.0 / 南北 0.8 / 东西 0.6。
  MC 不用真实光照算面亮度，而是硬编码这几个系数 —— 正是这张表让它的方块有
  "稳定、干净、一眼认得出"的立体感，而不是随太阳角度乱变。顶点色在线性空间，
  所以实际填的是 `visual^2.4`：顶面 `1.20~1.32`、南北 `0.80 / 0.74`、东西 `0.42 / 0.38`。
- **不做 UV 随机旋转**：Minecraft 的方块纹理朝向是固定的，一片草地就是同一个
  16×16 图案重复 —— 这正是它的样子，随机旋转反而"不像"。
- **色差只留极轻一档**（`0.96~1.06`）：MC 在同一个 biome 内草地颜色完全一致，
  原版纹理本身已带像素噪点，再叠大振幅色差会变成"花地图"。
- **水面必须比地面低 1/8 格 + 波纹**（`ty === 5` 的分支）。MC 的水方块高 14/16，
  水面比相邻地面低 `0.125` —— 这是湖岸出现"一圈浅色边"的原因，
  不做的话水面和地面齐平，湖看起来像"地上刷了块蓝色油漆"。
  再叠两层 `vnoise` 的轻波纹（振幅 ±6%，大了变脏水面）。
  水色 `FLOOR_SKIN[5].color = 0x2f66c8`：原版常量 `0x3f76e4` 乘灰度水贴图
  （均值 188）再经 1.15 曝光，屏幕上是**刺眼的荧光蓝**，压到 `0x2f66c8` 才对。

### 角色（`src/three/mcModel.js` —— Minecraft 原版模型）

2026-10-05 从"纯色方块人"换成**原版模型 + UV 展开**。纯色方块拼的角色，
比例和配色再准也不是 Minecraft —— 角色的脸、衣服、花纹在原版里是**贴图**。

- **MC 的 cube UV 规则**：给定皮肤图上的起点 `(u,v)` 和尺寸 `(w,h,d)`，
  六个面占的矩形是固定的（`up` 在 `(u+d, v)`、`north`/脸 在 `(u+d, v+d)`、
  `south` 在 `(u+d+w+d, v+d)`…）。`cubeRects()` 就是这张表，
  写错任何一个面的位置，脸就长到后脑勺上去了。
- **坐标系**：MC 的模型 y 轴**向下**（脚在 y 大处），本项目统一转成「脚底 0、向上为正」。
- **1 MC 像素 = 1/16 格**；玩家模型 32px 按 1.8 米高换算 → `PX = 1.8/32 = 0.05625`。
  物品因此从 0.98 米长到 1.8 米，**视高 `EYE` 同步改成 1.62**（MC 原版值），
  `src/sim/entities.js` 的命中射线起点、敌人 `height` 也必须跟着改 ——
  三处不一致就会出现"准星瞄着头、射线从胸口穿过"。
- 节点结构（head / body / armL / armR / legL / legR）与旧模型一致，
  所以 `animateHumanoid` / `animateSpider` 一行都不用改。
- 骷髅皮肤是 64×32，左右肢体共用一块 UV（`limb64: false`）；玩家/僵尸/赫斯克是 64×64。

### 武器与第一人称手臂

- **必须显示 MC 原版方块手臂**：没有手的枪在屏幕上就是"飘着的 T 形积木"，
  无论怎么调比例都像锤子。手臂取玩家皮肤的右臂区（4×12×4）。
- **手臂的朝向与尺寸是本项目最反复的一个坑，四条错法全部记录在
  `models.js` 的 `hand()` 注释里**，改动前务必读完。核心结论：
  - 角度不是关键，**尺寸才是**。手臂几何 12 MC 像素 = 0.75 米，
    乘 `ARM_TO_BLOCK`(1.111) 后是 0.83 米；放在离相机 0.55 米处，
    屏幕半高只有 `0.55 × tan36° = 0.40` 米 → **手臂占屏高 2 倍**，
    必然贯满画面。无论怎么转都是一根巨大的青绿柱子。
  - 正确做法：`ARM_VISIBLE_SCALE = 0.42`，**只露出约 0.35 米**（占屏高 44%，
    正是 MC 里手臂的占比），位置固定在画面右下角
    `(0.105, -0.205, -0.075)`，`rotation.set(-1.30, -0.42, 0.10)`。
  - `rotation.y` 必须是**负值**：手臂是 `weaponRoot` 的子节点，而
    `weaponRoot.rotation.y = 0.42`，给 +0.42 会叠加成 0.84 把头扭过去。
- 材质 `color` 与贴图**相乘** —— 贴图已带最终色时 `color` 必须接近白，
  否则"木色贴图 × 木色"≈ 深褐，整把枪糊成一坨看不出结构。
- 武器视模**明度分三档**（亮银 `0xccd4de` / 中灰 `0x8a929d` / 深灰 `0x474d56`）+ 深棕握把：
  曾经三档灰全挤在 `0x7e~0xc0`，在明亮光照下糊成一整块灰板。
  握把后倾 `rotation.x ≈ -0.25`，`rotation.y = 0.42`：第一人称是"从正后方看枪的横截面"，
  不外偏就只能看到几层方块叠起来，毫无纵深。
- `userData.muzzle` 必须落在枪管末端，`ensureWeapon` 用 `WEAPON_SCALE` 统一换算火焰位置
  —— 两边各写各的常量会让火焰飘在枪管前 0.3 米，屏幕上就是个白方块。
- **视模距离 `VIEW_Z = -0.55` 与缩放 `WEAPON_SCALE = 0.56` 是两个独立自由度**：
  距离决定"手臂多大"，缩放决定"枪多大"。曾经为了缩小长枪去推远距离
  （`-1.15` / `0.46`），结果手臂跟着变小、枪小到认不出。
  **要缩小枪就改 `WEAPON_SCALE`，不要动 `VIEW_Z`。**

## 血泪结论（勿回退）

- **⭐ 改完源码必须 `vite build`，否则看到的一直是旧画面**
  `server.js` 的静态目录**优先服务 `dist/`**（见 `server.js` 第 50 行附近的
  `distRoot` 逻辑），只有 dist 里找不到才回落源码根。
  `http://127.0.0.1:8080/` 返回的是 `assets/index-<hash>.js`（构建产物），
  **不是 `src/client/main.js`**。
  这一条曾导致连续 6 轮"改了看不见效果"：改 `alphaTest`、改 `maxMipLevel`、
  改人物尺寸，全都在改浏览器**根本没加载**的文件，截图当然一模一样。
  **排查任何"改了没反应"的问题，第一步先确认 `curl -s http://127.0.0.1:8080/ | grep assets/`
  返回的哈希和自己刚构建的是否一致。**
- **顶面绕序**：地面与墙顶的 +Y 面必须按"从外侧看逆时针"给顶点，否则被背面剔除
  —— 现象是"整个世界像悬空在灰色虚空里、看不到墙顶"，曾经出现过的头号画质 bug。
- **树叶的"蓝白网格"是贴图镂空规律，不是 mipmap 问题**。
  远处树冠变成蓝白点阵，曾误判成三个原因，全部被对照实验否定：
  `maxMipLevel` 设 0（关 mip）→ 网格仍在；设 ∞ → 画面干净无越界；
  `alphaTest` 0.1→0.5 → 画面零变化；按连通块大小填 → 镂空率几乎不动。
  **真实成因**：原版 `oak_leaves` 的 32.8% 镂空在**垂直方向完全对齐**，
  16 行里每行透明位置一模一样（`##.#.##.####..##` 重复 16 次），
  形成 **8 条贯穿整格的竖缝**；远处一缩就压成规则条带。
  解法在 `tools/build-mc-atlas.py` 的 `thin_leaf_alpha()`：
  **隔 3 行填 1 行打断长条**，把竖缝切成散点。镂空率几乎不变（32.8%→30.1%），
  但远处树冠收成完整绿团。
- **天空云必须用射线-云平面求交**：写 `uv = d.xz / d.y * k` 这种近似投影，
  天顶处 `d.xz ≈ 0`，整个天空只覆盖两三个格子 → 一块云占半个屏幕，
  天上像插着几块巨大的白多边形板。正确做法是 `t = CLOUD_H / d.y; p = d.xz * t`，
  再按 `CLOUD_CELL` 量化；`camXZ` uniform 提供视差。
- **顶点色在线性空间**：AO / 色差 / 各面明暗差的数值都要按 `k_linear ≈ 视觉比^2.4` 给。
  给 0.7 想"暗 30%"，屏幕上只暗 13%，等于白调 —— 这条坑了整整一轮美术优化。
- **`pushSide` 按 1 米分段**，不能用 `h/round(h)` 等分（墙高表全是 2.85 / 2.45 这种非整数）。
- **`normalBias` 不能小于 0.04**：0.028 时大平面（地面）会大面积自遮挡，
  整个地面像蒙了层灰 —— 比"影子略微偏移"难看得多。
- **SwiftShader（软件 GL）下阴影贴图会正常渲染但屏幕上不出现影子**
  （draw call 会翻倍、`shadowMap` 各项状态都正常，就是没有影子）——
  这是软件渲染器不支持深度比较采样，**不要据此去改阴影配置**，真机 GPU 上是好的。
  取景脚本里想确认阴影得换真机；`tools/showcase.cjs` 的 `-f-shadow` / `-g-dark` 两个场景
  是为排查这件事加的。
- **阴影相机**：改过 `shadow.camera.left/right/top/bottom` 之后必须手动
  `updateProjectionMatrix()`，否则阴影相机还是构造时的 ±5 默认框，稍远就没有影子。
- **金属材质必须有环境贴图**：没有 `scene.environment` 时 `metalness > 0` 会渲染成死黑
  （金属没有漫反射），所以启动时用一张天空渐变烤 PMREM 当 IBL。
- **地形重建立必须带 seed**：渲染器的世界缓存 key 以前只有 `SIZE|墙数组长度`，
  重开一局换了 seed 不重建 → 碰撞用新地图、画面是旧地图，直接穿模。
- **天空球不能关 matrixAutoUpdate**：它每帧跟着相机走，一旦关掉自动矩阵，
  玩家走远后相机跑到球外面，天上会出现一道"巨大蓝色圆弧"。
- **贴图基色在线性空间偏暗**：`toneMappingExposure` 需要略大于 1（当前 **1.15**，曾用 1.35 → 过曝），
  且 `WALL_SKIN/FLOOR_SKIN` 的 color 只能做轻微偏色（一律 ≥0xe0），给深色会把贴图二次压暗
  —— bedrock 曾经用 `0xa8a8b0` 乘中灰贴图，变成一整面突兀的近黑墙。
- **CSS 的 `.show` / `.pop` 曾经完全没有样式规则**（不是写错，是根本没有）：
  开场横幅永久挂在屏幕正中、提示条常驻、击杀飘字没有动画。补在 `css/style.css` 末尾。
- **`.screen` 的 flex 居中**要配 `align-items:flex-start` + `.panel{margin:auto}`，
  否则内容高于屏幕时顶部被裁且滚不到。
- **指针锁定必须门控**：只有 `isPlaying()` 为真才 `requestPointerLock()`。
- **鼠标 movement 尖峰**：`|movementX| > 180` 直接丢弃 + 锁定后 3 帧 grace。
- **流场/寻路坐标必须 `Math.floor`，禁止 `Math.round`**（格角 x.5 会吸附到隔壁格 → 敌人冻结）。

## 开发流程

```bash
npm run build                         # ⭐ 必需：server.js 优先服务 dist/，
                                      #    不 build 就永远看到旧画面（见血泪结论第一条）
node server.js                        # 起静态服务器（打印局域网地址）
npm run verify                        # 必需：模拟层回归
node tools/playtest.cjs               # 必需：可玩性端到端（需 server 已启动）
node tools/ui-check.cjs               # 改动 UI 后跑
node tools/showcase.cjs <tag>         # 改动渲染后跑，产出 artifacts/<tag>-*.png
node tools/weaponshot.cjs <tag>       # 改动武器/手臂后跑，5 把枪各一张
node tools/nettest.js                 # 改动联机后跑
```

**改原版纹理的完整链路**（只在需要换素材时走）：

```bash
python tools/fetch-mc-textures.py     # 下载 client jar 并抽取（约 40MB，产物入库）
python tools/build-mc-atlas.py        # 重新拼图集 + 生成 base64 内联 JS
npm run build                         # 别忘了这一步
```
